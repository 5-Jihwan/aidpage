# AidPage 다국어 — 언어 선정·글꼴·구조 (2026-10-07)

## 1. 왜 바꾸나
- 상단 버튼이 `🌐 언어`(현재 언어로 번역된 글자)라서, 한국어를 모르는 방문자는 🌐 아이콘 하나로 알아채야 했다.
- 브라우저 언어 자동 감지가 ko/en만 봤다. 일본어 폰으로 들어와도 영어.
- 코드 곳곳의 `언어 === 'en'` 분기 약 40곳이 "영어가 아니면 한국어"로 되어 있어, 제3 언어를 넣으면 지명·규칙·시설명이 한국어로 섞여 나온다.

## 3. 외국인 자격 문제 (번역보다 먼저)
- 앱에 이미 `외국인 주민이에요` 선택지와 `fr.*` 안내(국적 무관 이용 가능 항목 / 외국인등록 조건 항목)가 있다.
- 외국어판 첫 화면에 한 줄 고지 추가(`wel.xlat`): 번역본이며 한국어 원문 우선, 상당수 제도는 피해 지역 주민등록·외국인등록 필요.
- 결과 화면 머리에 `lang.rulesEn`: 항목명·금액·근거는 영어로 나온다는 고지(규칙 번역은 영어본뿐).

## 5. 구조
- `js/i18n.js` — `LANGS` 7개(언어 이름은 그 언어 표기, 국기 없음), 브라우저 언어 자동 감지(없으면 en), `t()` 대체 순서 해당 언어 → en → ko.
- ko/en은 i18n.js 안에, 나머지는 `js/i18n/<lang>.js`를 고를 때만 `import()`. 실패하면 en.
- 버튼 3곳(상단 메뉴·서랍·첫 화면)은 `app.js buildLangButtons()`가 LANGS로 생성. 상단 버튼 = `🌐 한국어 · Language`(영어 화면은 `🌐 English`).
- 영어 분기 → `getLang() !== 'ko'`: 지명 name_en·rules/en.json·welfare_en·시설명은 모든 외국어에서 영어본. 숫자·날짜는 `Intl`에 언어 코드 그대로.
- 읽어주기 TTS: 언어별 BCP-47(ja-JP·zh-CN·vi-VN·es-ES·fr-FR).
- 사전은 sw.js 프리캐시에 넣지 않는다(모든 방문자가 310 KB를 매 배포마다 받게 되므로). 한 번 고른 언어는 networkFirst 캐시에 남아 오프라인에서도 유지되고, 오프라인에서 처음 고르면 영어로 떨어진다.
- 부팅 때 사전이 3초 안에 안 오면 영어로 먼저 띄우고, 도착하면 `i18n:late` 이벤트로 전체 재렌더(재난 때 빈 화면 방지). 공유 링크의 `l=`는 사전 로드가 끝난 뒤 결과를 그린다(`await applyLangParam`).
- 언어 저장값은 '고른 언어'로 남긴다 — 로드 실패로 영어가 떠도 다음 방문에 재시도.
- atlas.html은 `<html data-i18n-static>`으로 자동 사전·글꼴 로드를 건너뛴다.
