# SafePic 외부 API 통합 설계 v1

작성 2026-08-21 · 대상: 기상청(공공데이터포털 + API허브) · 산림청 · 국가법령정보 · 복지로/사회보장정보원 · 빅카인즈 · SerpApi · Cloudflare Worker
전제: SafePic은 정적 사이트(GitHub Pages). **브라우저에 키를 두지 않는다.** 모든 외부 호출은 ① GitHub Actions 스냅샷 또는 ② Cloudflare Worker 프록시를 거친다.

## 1. 아키텍처

```
                     ┌─ GitHub Actions (cron) ─────────────────────┐
  기상청·산림청·복지로 ─┤  scripts/fetch_live.py  → data/live/*.json  ├─ git push → Pages
  법령(일배치)        └─ scripts/fetch_daily.py → data/ref/*.json   ┘

                     ┌─ Cloudflare Worker  safepic-api.<subdomain>.workers.dev ─┐
  브라우저 ── fetch ──┤  /news?sgg=11620   → 빅카인즈 (KV 캐시 30분)               │
                     │  /law?id=...&art=  → 국가법령정보 (KV 캐시 24h)            │
                     │  /notice?sgg=      → SerpApi (KV 캐시 24h, 일 쿼터 가드)    │
                     └─ Origin 허용목록 · IP당 분당 30회 · 키는 Worker Secret ──────┘
```

### 1.1 Actions(스냅샷) 원칙 — 기존 `fetch_live.py` 규약 유지
- 키 없음 → 섹션 `status:"no_key"`, 파일 안 건드림. 오류 → 이전 파일 유지 + `status:"error:<code>"`. **절대 raise 안 함.**
- 호출 상한 `LIVE_MAX_CALLS`(현재 560/run). 아래 쿼터 계산에 맞춰 재조정.
- 스냅샷 파일은 **시군구(250) 단위**가 기본 해상도. 동(3,500) 단위 호출은 하지 않는다(쿼터·용량 둘 다 초과).
- 새 파일은 전부 `data/live/` 또는 `data/ref/`에 두고 `live.yml`의 `git add` 목록에 추가.

### 1.2 Worker(온디맨드) 원칙
- 무료 플랜: 일 100,000 요청, KV 읽기 100,000/일·쓰기 1,000/일. 캐시 히트는 KV 읽기만 소모 → 쓰기 1,000/일이 실질 상한이므로 **캐시 TTL을 길게**(뉴스 30분, 법령 24h, 공고 24h).
- `Access-Control-Allow-Origin`: `https://5-jihwan.github.io` 와 `http://localhost:*`만.
- 레이트리밋: IP당 분당 30회(Worker 내 메모리 + KV 카운터). 초과 시 429.
- 외부 API 키는 `wrangler secret put`으로만. 코드·repo에 절대 노출 금지.
- 실패 시 빈 배열 + `status` 반환. 브라우저는 Worker 실패해도 화면이 깨지지 않게(뉴스·법령 블록만 숨김).
- 배포: `wrangler deploy` 수동. 코드는 repo `worker/` 폴더에 둔다(키 없음이므로 공개 OK).

### 1.3 키 체계 (내일 07:00 토큰 초기화 후 확인할 것)
| 키 | 발급처 | 커버 | 보관 |
|---|---|---|---|

## 2. 기상청

### 2.1 쓰는 것 / 안 쓰는 것
- **쓴다**: 예특보(단기예보·초단기실황·특보), 지상관측(ASOS 일자료 — 폭염일수 통계), 레이더(합성 이미지), 위성(천리안 RGB 이미지), 융합기상(생활기상지수·가뭄), 지진화산(지진통보), 태풍(경로).
- **안 쓴다**: 해양·고층·수치모델·항공·세계·산업특화(에너지·수자원·농업·교통·태양광). 사용자(주민·어르신)와 무관.

### 2.2 쿼터 계산 (공공데이터포털 개발계정 기본 10,000/일/서비스)
| 서비스 | 호출 단위 | 시군구 250 × 주기 | 일 합계 | 판정 |
|---|---|---|---|---|
| 초단기실황 `getUltraSrtNcst` | 시군구 대표 nx,ny | 250 × 24회(매시) | 6,000 | OK |
| 단기예보 `getVilageFcst` | 시군구 대표 nx,ny | 250 × 8회(3시간) | 2,000 | OK |
| 특보현황 `getWthrWrnList` | 전국 1회 | 48회 | 48 | OK |
| 생활기상지수(자외선·체감·대기확산) | 시군구 | 250 × 2회 | 500 | OK |
→ 현재 30분 cron에서 **초단기실황은 정시 실행분만, 단기예보는 02·05·08·11·14·17·20·23시 발표 직후 분만** 호출하도록 분기. `LIVE_MAX_CALLS` 600 유지.

### 2.3 출력 스키마 `data/live/weather.json` (확장)
```json
{ "updated": "...", "status": "ok", "base_time": "...",
  "by_sgg": { "11620": {
     "t": 31.2, "feels": 34.8, "reh": 62, "wsd": 3.1, "vec": 225, "rn1": 0.0,
     "pty": 0, "sky": 3, "tmx": 33, "tmn": 25, "pop": 30,
     "uv": 8, "dust_diff": 2,
     "fcst3h": [ {"t":"1500","ta":32,"pty":0,"pop":20,"wsd":3}, ... 8개 ] } } }
```
바람 방향 `vec`(도)과 `wsd`는 지도 화살표용. `fcst3h`는 "3시간 뒤" 카드용.

### 2.4 지도 히트맵 — 항목별로 다르게
격자 5km 래스터는 공공데이터포털 API로는 못 받는다(지점 호출만 가능). **1차는 시군구 색면(choropleth)**, 2차에 API허브 격자자료로 래스터 승격.

| 항목 | 표현 | 스케일 | 근거 |
|---|---|---|---|
| 기온 | 색면 | -15→40℃, 파랑-흰-주황-빨강(기존 날씨 체계) | 기상청 분포도 관례 |
| 체감온도 | 색면 | 31/33/35/38 경계에서 단계 색 | 폭염특보 기준(체감 33 주의·35 경보) |
| 습도 | 색면 | 30/50/70/90 | 건조주의보 기준(실효습도 35%) 연동 |
| 미세먼지 PM10 / PM2.5 | 색면 | 좋음·보통·나쁨·매우나쁨 4단계(기존 `pmGrade`) | 에어코리아 등급 |
| 강수 | **아이콘+색면** | pty(없음·비·비/눈·눈·소나기) 아이콘, rn1 강도 색 | 기상청 아이콘 |
| 바람 | **화살표 심볼 레이어** | `vec`로 회전, `wsd`로 길이·굵기, 14m/s↑ 주황 | 강풍주의보 기준 |
| 구름 | 위성 이미지 오버레이 (2.6) | — | — |

MapLibre 구현: 기존 `fill` 레이어의 `fill-color`를 `['match', ['get','sgg_cd'], ...]` 또는 `feature-state`로 주입. 바람은 `symbol` 레이어 + SVG 화살표 이미지 + `icon-rotate: ['get','vec']`. 항목 전환은 현재 `#wxsel` 체크박스를 **라디오(한 번에 한 레이어)**로 바꾸고, 패널 숫자 카드는 기존처럼 다중 선택 유지.

### 2.6 레이더·위성 오버레이 (API허브)
- 레이더 합성 이미지(전국, 10분) → Actions가 PNG 저장 `data/live/radar.png` + 경계 좌표 JSON. MapLibre `image` 소스로 얹기, 불투명도 0.5.
- 천리안 2A RGB(한반도, 10분) → 동일 방식 `data/live/sat.png`. "구름 지표"는 이 이미지가 곧 지표.
- 용량: 이미지 2장 × 144회/일 git 커밋은 repo 비대화 → **커밋하지 않고 Worker KV에 저장**하거나, 커밋하되 최근 1장만 덮어쓰기(git 이력은 쌓임). **권장: Worker `/radar` 엔드포인트가 API허브에서 받아 KV 캐시 10분** — Actions 커밋 없음.

### 2.7 지진·태풍
- 지진통보(API허브): 규모 3.0↑ 발생 시 `data/live/quake.json` + `.hot` 플래그 → cron 10분 전환 힌트(기존 메커니즘). 브라우저는 `quake.json`이 24h 이내면 지진 대피소 레이어 자동 ON + 매핑표 문구.
- 태풍정보: 활성 태풍 있을 때만 `data/live/typhoon.json`(예상경로 좌표·반경) → `line` + `circle` 레이어.

### 2.8 통계(지상관측 ASOS 일자료)
- 시도 대표 지점 ~100개, 연 1회 배치로 **폭염일수·열대야일수·최대일강수** 최근 10년 → `data/ref/climate_stats.json`. 내 동네 카드 "올해 폭염일수 23일, 10년 평균 12일". 이게 "재난 확률·통계 정교화"의 첫 조각.

## 3. 산림청

| API | 성격 | 경로 | 화면 |
|---|---|---|---|
| **산사태위험지도**(산림공간정보 FGIS, 등급 1~5, 정적) | 공간 데이터(WMS/WFS 또는 SHP) | 1회 적재 → 관악구 격자에 `landslide_grade` 컬럼, 전국은 WMS 타일 오버레이 | 격자 속성 칩 + 레이어 |
| **산사태예측정보**(`predictionInfoService`, 이미 URL 있음) | 실시간 주의보·경보 (시군구) | Actions 30분 → `alerts.json`에 `landslide` 섹션 | 특보 카드, 매핑표 "비탈 아래 집은 지금 나오세요" |
| **산불위험예보**(국립산림과학원, 시군구 위험지수 0~100 + 등급) | 실시간 | Actions 1일 2회 → `data/live/fire.json` | 색면 레이어 + 건조 카드 |
| **산악기상정보**(산악기상관측망 AWS ~460지점) | 실시간 관측 | Actions 1시간 → 산간 시군구 보강 | 진안·무주 같은 산간 지역의 실제 기온·풍속(기상청 대표지점보다 정확) |

산사태위험지도 + DEM 경사(격자에 이미 있음) + 침수흔적 → **격자 H(hazard) 벡터가 수해·산사태 2축**이 된다. 탭③ SPA의 b₂·H 항에 직접 들어감.

## 4. 국가법령정보 OPEN API (open.law.go.kr)

### 4.1 연결 대상
`rules/*.json` 51개에 필드 추가:
```json
"law": { "mst": "법령일련번호", "name": "자연재난 구호 및 복구 비용 부담기준 등에 관한 규정", "art": "제9조", "annex": "별표1" }
```
- 재난 및 안전관리 기본법 §66 · 자연재난 구호 및 복구 비용 부담기준 등에 관한 규정 §9·§12·별표1 · 의연금품 관리·운영 규정(행정규칙) · 풍수해·지진재해보험법 시행령.

### 4.2 일배치 `scripts/fetch_daily.py` (Actions, 03:00 KST)
1. 현행법령 본문 조회 → 규칙이 참조하는 조문·별표 텍스트만 추출 → `data/ref/law/<mst>.json`.

## 11. 탭③ SPA — 기존 방법론 조사 결과 (2026-08-21)

**질문**: "같은 1억 원으로 어느 격자의 안전 확률이 가장 많이 오르나"(SPA, WPA 비유)에 해당하는 확립된 방법이 있는가?
**답**: 핵심 계산(ΔE[Loss]/Cost)은 이미 표준이 있다. 새 추정량을 발명하지 말고 **기존 표준을 격자·시민공개·형평가중으로 재포장**하는 것이 SafePic의 기여.

### 11.1 확립된 방법
| 방법 | 기관 | 핵심 | SafePic에 가져올 것 |
|---|---|---|---|
| **BCA / BCR** (Benefit-Cost Ratio) | FEMA (미) | 편익 = 회피손실(avoided losses)의 현재가치, 비용 대비 비율 ≥1.0이면 타당. 정책 종합 BCR ≈ 4:1 | `Eff_i(a) = ΔE[Loss]_i / Cost(a)` 는 곧 BCR. 할인율(FEMA 2024: 3.1%) 적용 |
| **EAD** (Expected Annual Damage, 연평균피해액) | FEMA Hazus·USACE | 재현기간별 피해액 × 초과확률을 적분 | 격자 i의 E[Loss]_i 정의 그대로 |
| **MD-FDA** (다차원 홍수피해산정법) | 국토부·KDI 예타 표준 (한) | 침수심별 **피해율 곡선** × 자산(건물·가재·농경지·인구) → 연평균피해경감기대액. GIS 격자 연동이 원래 설계 | 침수심-피해율 곡선(공개 표)을 그대로 H→Loss 변환에 사용. 한국 공식 방법이므로 근거 제시가 쉬움 |
| **자연재해위험개선지구 투자우선순위** | 행안부 관리지침 (한) | 위험도·피해이력·인구·비용 등 항목 점수제로 정비사업 순위 | 격자 우선순위의 공식 대조군. 개선지구 지정 현황 CSV를 레이어로 |
| **Mitigation Saves** | NIBS (미) | 재해예방 투자 1$당 회피손실 6$ (종류별 2~11$) | "1억 원이면 얼마를 막나" 기준값·문구 근거 |
| **경제적 최적 방어수준** | Eijgenraam 등, 네덜란드 Delta | 비용·피해의 동적 최적화로 제방 높이 결정 | 슬라이더(투자액→안전도) UX의 이론적 선례 |

### 11.2 SafePic이 추가하는 것 (기존에 없는 부분)
1. **격자(H3 res9) 단위 공개 대시보드** — 위 방법들은 사업 단위·내부 문서. 격자로 시민이 직접 보는 화면은 없다.
2. **"안전 확률" 프레이밍** — EAD(원)를 σ(…) 확률로 바꿔 "이 동네가 안전할 확률 71% → 84%"로 읽게 함. 금액보다 어르신에게 직관적. 수식은 유지하되 내부 계산은 EAD로.
3. **형평 가중** — 고령1인세대·취약계층 비율(격자에 이미 있음)로 Loss를 가중(예: 인명 가중 = 인구 × 취약비율 × VSL). 행안부 점수제도 인구는 보지만 취약성 가중은 약함.
4. **수해+산사태 2축 H** — 침수흔적·침수심 + 산사태위험등급(산림청)을 같은 격자에서 합산.

### 11.3 구현 결정
- 새 알고리즘 개발 **안 함**. E[Loss]_i = Σ_재현기간 P(r)·Loss_i(depth_r) 를 MD-FDA 피해율 곡선으로 계산, SPA_i(a) = E[Loss]_i − E[Loss]_i′ 를 비용으로 나눈 BCR을 보여주고, 확률 표현은 SE_i = 1 − E[Loss]_i / MaxLoss_i 로 정의해 σ 수식과 일관되게.
- 대책 a의 카탈로그(비용·효과): 배수펌프 증설, 역류방지시설, 반지하 차수판, 옹벽·사면보강 — 행안부 개선지구 정비사업 단가 사용.
- 검증: 관악구 결과를 **자연재해위험개선지구 지정 현황**과 대조(지정 지구가 상위 격자에 들어오는지) → 방법·한계 탭에 정확도 기록.
- 문서: 방법·한계 탭에 "FEMA BCA·MD-FDA를 격자에 적용, 새 모델 아님"을 명시(신뢰도 ↑, 과대주장 방지).

출처: FEMA BCA(fema.gov/grants/tools/benefit-cost-analysis), FEMA Policy 206-23-001(2024 할인율), 다차원 홍수피해산정방법(I) 원리 및 절차(KCI), 도시지역 침수피해액 산정을 위한 다차원법 적용(KCI), 자연재해위험개선지구 관리지침(행안부 고시 2023-37호), 행안부_자연재해위험개선지구 현황(data.go.kr 15133362).
