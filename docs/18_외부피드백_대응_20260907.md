## 1. 청구비용으로 성과 재기 (The Claiming Costs Scale)

- **요지**: 성과지표를 "정보를 얼마나 보여줬나"가 아니라 "지원을 찾고 신청하는 부담이 얼마나 줄었나"로. 청구비용은 정보비용·과정비용·사회심리비용의 세 묶음이고, 검증된 9문항 척도(CCS)가 있다.
- **현재**: 방법·한계 탭 `about.p2`가 Herd & Moynihan(2018)의 학습·순응·심리 비용을 인용해 문제를 정의한다. 측정은 없다. 익명 카운트 4종은 '얼마나 쓰였나'만 말해 준다.
- **대응**
  1. RQ4(docs/04 §3-1: 매칭 카드가 회복 못한 집단의 신청 의도·행동을 바꾸는가)의 1차 결과변수를 CCS-9로 잡는다. 설계는 카드 있음/없음 두 조건 온라인 실험 + 주민센터 파일럿, 사전·사후.
  2. CCS 세 차원 ↔ AidPage 기능 대응표를 실험 문서에 둔다: 정보비용 ↔ 규칙 카드·기한·"소식 없음" 경로 / 과정비용 ↔ 서류 목록·어디에·대리 확인 모드 / 심리비용 ↔ 낙인 완화 문구·익명·심사하지 않음.
  3. 사이트 안 미니 설문(선택, 결과 화면 하단, 3문항: "찾기 쉬웠다 / 어디에 가야 할지 알겠다 / 신청할 마음이 생겼다", 5점): 익명 카운트와 같은 통로(`stat`)로 응답 분포만 집계. 자유 서술·식별자 없음. 원칙(about.n2) 유지.
- **주의**: CCS는 사회급여 청구 맥락에서 개발된 척도라 재난지원 문항으로 옮길 때 문항 타당화(소규모 인지 인터뷰)가 먼저다.

## 2. '지금 할 일' — 위험 정보 + 행동, 재난 유형별 템플릿

- **요지**: 경고 메시지는 위험 평가(무엇이·어디서·언제·얼마나)와 구체 행동을 같이 줘야 하고, 순응을 끌어내는 요인이 기상·폭력·감염병에서 달라 하나의 틀을 재사용하면 안 된다.
- **현재**: `todoItems()`가 최대 3개를 고른다 — 특보(유형 11종 × 주의보/경보 = 22문장), 계절 7, 프로필 6, 상시 2, 상황 2. 문장은 유형별로 다르지만 **카드 구조는 한 틀**: `[출처] 행동 한 문장 (+시설 보기 버튼)`. 위험 정보(현재 강수량·이력)는 다른 카드(`risk.*`)에 흩어져 있다.
- **대응**
  1. 위해군을 둘로 나눠 템플릿을 분리한다.
     - **급성**(호우·산사태·해일·지진·태풍·강풍): 위험줄(특보 등급 + 관측값 + 내 동 이력) → 즉시 행동 1개 → 효능문("지금 30분 안에 이렇게 하면 됩니다") → 장소 버튼(대피소·지하차도 회피).
     - **완만**(폭염·한파·미세먼지·건조·대설): 취약군 표시(65세+·야외 노동·아이) → 시간대 행동("낮 12~17시 외출 줄이기") → 쉼터 버튼 → 다음 갱신 시각.
  2. `todo` 항목 스키마를 `{hazard, level, risk_line, action, efficacy, time_window, place_kind, src}`로 확장하고 i18n 키를 `todo.alert.<hazard>.<lv>.<field>`로 나눈다. 기존 22문장은 `action`으로 이관.
  3. 한국어 Warning Lexicon(RQ1)과 같은 데이터로 관리한다 — 문장 편집이 곧 실험 자극이 되게.
- **하지 않을 것**: 폭력·감염병 유형은 범위 밖(장소형 재난만).

## 3. 개인화 — "왜 나와 관련되는지"를 보여주기

- **요지**: 개인화의 핵심은 수신자의 지역·조건과 정보가 연결되는 **이유**를 드러내는 것. 한국 무선 긴급경보 연구(울산, 비실험)는 직접 관련 고지가 반복 일반 지침보다 효과적일 수 있음을 시사하지만 전국 인과로 일반화하면 안 된다.
- **현재**: 지원 찾기 결과의 `whyHTML`이 충족 조건(예: "주택 침수 · 세입자")을 보여준다. 지역 서랍 '왜 이 타입인가'가 임계 대비 값을 보여준다. **'지금 할 일'과 특보 배너에는 관련 이유가 없다** — 왜 이 동에 이 문장이 떴는지 알 수 없다.
- **대응**
  1. '지금 할 일' 각 항목 아래 한 줄: `관악구 호우주의보(기상청 12:00) · 신림동 격자 15%에 침수 이력` 처럼 **내 위치 + 발동 조건 + 이력**을 결합. 데이터는 이미 있음(warningsFor, gridCells).
  2. 특보 배너(`bn`)에도 같은 줄.
  3. 효과 주장은 하지 않는다. 방법·한계에는 "관련 이유를 함께 보여주는 방식은 문헌의 가설이며 아직 검증 전"으로 적고, RQ2 A/B(이유 줄 있음/없음)로 잰다.

## 4. '해당 가능성' 설명 구조

- **요지**: 규칙 기반 판정의 인간 중심 설명은 **결론 → 핵심 이유 → 충족·미충족 조건 → 근거 조문·기준일·출처** 순이 유망한 초기 가설. 내용·전달 방식·사용자별 적응을 함께 설계.
- **현재 카드 순서**: 라벨+금액(결론) → 요약 → 충족 조건 칩(`_why`) → 근거 조문·기준일·출처 → 조문 펼침(law fold). 근접 탈락(`res.miss`)은 별도 블록에 "→ 조건"으로 표시.
  - 빠진 것: **한 줄 이유**("침수 세대라 세대당 정액 대상"), **미충족·확인 필요 조건**(위저드가 묻지 않는 실거주·피해신고 완료·소득 기준), 카드 안에서의 ✓/?/✗ 구분.
- **대응**
  1. 규칙 스키마에 `reason`(한 줄)과 `checks: [{key, label, ask: 'wizard'|'office'|'self'}]` 추가. 위저드가 묻는 조건은 ✓/✗, 나머지는 `?` "주민센터에서 확인"으로.
  2. 카드 재배치: `결론(가능·확인 필요·해당 없음)` → `reason` → 체크리스트 → 근거(현행 유지). 근접 탈락 블록은 유지하되 같은 체크리스트 부품을 쓴다.
  3. 사용자별 적응은 이미 있는 두 축을 쓴다: 대리 확인 모드(인쇄용 축약)와 큰 글씨 모드. 여기에 "짧게/자세히" 토글 하나(결론+이유만 ↔ 전체).
- **연동**: 규칙 51개에 `reason`·`checks`를 채우는 작업은 S3(법령 API로 law.mst 채우기)과 같은 편집 회차에 한다.

## 5. 지오프라이버시 — 최소 행정구역까지만

- **요지**: 위치는 판정에 필요한 최소 단위까지만 처리. 정밀도를 낮춘 위치 공유로도 서비스 효용은 얻어지며, 위치 이력은 건강·소비·사회적 지위까지 추론시킨다.
- **현재 점검(코드 기준)**
  - GPS 버튼: 브라우저 안에서 시·도→시·군·구→읍·면·동 폴리곤 판정 후 **동 코드**로 선택. 원좌표는 메모리(`state.gps`)에만 두고 지도 점 표시·가까운 시설 도보 계산에 쓴다. 저장 안 함.
  - 저장·공유: 홈(`safepic.home`)=동 코드, 공유 URL=동/시군구 코드, 푸시 구독=시군구·시도·이름, 응급실·제보 조회=시군구 코드.
  - **예외 발견**: 주민 제보 전송(`postReport`)에 GPS가 현재 동 안이면 **원좌표 lon/lat**가 실려 서버(Cloudflare, 7일)로 간다. 지도 핀용.
- **대응**
  1. **(반영)** 제보 좌표를 소수 3자리(약 100 m)로 반올림해 전송한다. 핀 용도엔 충분하고 집 위치는 특정되지 않는다.
  2. 방법·한계 `about.n2`에 "위치는 읍·면·동 코드까지만 다루며, 제보에 붙는 좌표는 100 m 단위로 뭉갠다"를 한 문장 추가(다음 i18n 편집 때).
  3. 지오프라이버시 원칙을 docs/01 설계 원칙에 한 줄로 고정: "판정 최소 단위 = 행정동, 좌표는 저장·전송하지 않는다(제보 100 m 예외)".

## 6. 우선순위 제안

1. 제보 좌표 반올림 — 완료(이번 커밋).
