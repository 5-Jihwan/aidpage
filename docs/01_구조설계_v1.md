# 재난 지원 내비게이터 — 구조 설계 v1 (2026-08-21)

> 가칭. 이름 후보: **"내재난(Nae-Jaenan)"** / "피해 다음날" / "재난 나침반". 영문 repo: `disaster-navigator`.

## 0. 한 줄 정의
**"내 위치와 내 상황을 넣으면, 지금 할 일과 받을 수 있는 지원이 한 화면에 나오는 정적 웹 지도."**
부제(학술): 수요자 중심 재난 지원 큐레이션 + 격자 단위 방재 한계효용(SPA) 시각화 실증.

## 1. 문제 정의 (약한 부분 보강)

아이디어 단계의 "정보 홍수·공급자 중심·신청주의"를 **검증 가능한 세 주장**으로 바꾼다. 각 주장은 방법론 페이지에 근거와 함께 실린다.

### 주장 1. 정보는 많지만 "나에게 해당하는 것"을 찾는 비용이 전가돼 있다
- 근거: 재난 지원은 기본법 §66 한 조문 아래 대통령령 별표1 + 국토부/행안부/중기부 고시 단가 + 17개 기관 간접지원(규정 §12) + 의연금 규정 + 풍수해보험법으로 **5층 구조**. 일반 재난지역 25종 + 특별재난지역 13종 = **38종**을 한 곳에서 조건별로 보여주는 공적 화면이 없다(2026-08 조사).
- 행정학 틀: **Administrative burden**(Herd & Moynihan 2018)의 *learning cost* — "무엇이 있는지 알아내는 비용".
- 플랫폼 응답: 상황 → 항목 역매칭, 규칙 공개(Rules as Code).

### 주장 2. 전달체계가 공급자(부처·법령) 단위로 잘려 있다
- 근거: 생활안전지도(행안부)·floodmap(환경부)·보조금24(행안부 디지털정부)·국민안전24(피해신고)·희망브리지(의연금)가 각각 별도 사이트·별도 로그인. 2026-04-30 "국민안전24" 통합조차 *정보 포털 5개* 통합이지 지원 매칭은 아님. 2026-07-22 신설된 중앙합동 재난피해자 지원센터는 **오프라인** 원스톱.
- 틀: *compliance cost* — 서류·창구 반복.
- 플랫폼 응답: "피해사실확인서 1장으로 자동으로 열리는 것 / 따로 신청 / 기한 있음" 3열 분류. 타임라인.

### 주장 3. 신청주의는 가장 취약한 사람을 가장 먼저 탈락시킨다
- 근거: 규정 §9② "재난 종료일부터 10일 이내 피해신고" — 고령·독거·반지하·외국인 노동자는 기한을 모르거나 대리인이 없다. 2022-08 서울 반지하 침수 사망(관악·동작)은 *사전* 사각지대, 10일 기한 미신고는 *사후* 사각지대.
- 틀: *psychological cost* + 선제적(proactive) 급여 논의.
- 플랫폼 응답: D-day 타이머, **대리 입력 모드**, 격자별 "예상 피해 세대 vs 신고 건수" 갭 지도(사각지대 가시화 = 연구 기여).

### 한계를 먼저 말한다 (선배님의 "not exhaustive" 구조화)
- 이 사이트는 **심사 기관이 아니다**. 결과는 "해당 가능성"이며 최종 판단은 지자체.
- 단가·기한은 고시·중대본 결정으로 바뀐다 → 모든 숫자 옆에 `기준일·근거`.
- SPA는 공개 데이터 한계상 **가정 계수 기반 사고실험**이며 β 추정이 아니다.

## 3. 정보 구조 (IA)

```
[입구] 상황 카드 6장 (법령이 아닌 '상황'으로 진입)
 ├ 집이 잠겼어요        → ② 지원 찾기 (주택·침수 프리셋)
 ├ 가게가 잠겼어요      → ② (소상공인 프리셋)
 ├ 지금 대피 중이에요   → ① 지도 (대피소·특보 레이어 on)
 ├ 비 오기 전이에요     → ① 지도 + 보험 계산기
 ├ 가족이 다쳤어요      → ② (의연금 사망·부상 + 심리지원)
 └ 신고했는데 소식이 없어요 → ② 결과의 '절차 타임라인' 섹션

[지역 선택] 시·도 › 시·군·구 › 읍·면·동 (브레드크럼, 어디서든 변경) — 사람은 '동'으로 생각한다
[상단 띠] 오늘 우리 동네: 기온·체감·강수 + 발효 중 특보 + 재난문자 + 하천수위 (Actions 10~30분 갱신, '갱신 HH:MM' 표기)
           → 특보가 있으면 그 재난의 카드·지원·대피소가 자동으로 위로 올라옴 ("날씨가 필터")

[탭 ①] 지금 내 동네는   — H3 격자 지도 (위험·이력·취약·대피소)
[탭 ②] 나는 뭘 받을 수 있나 ★ — 위치 + 질문 5개 → 결과 한 장
[탭 ③] 어디에 먼저 써야 하나 — SPA 시나리오 슬라이더 + 갭 지도
[하단] 방법론 · 규칙 보기(JSON) · 변경 이력 · 출처 · 한계 · 정정 제안(GitHub Issue)
```
선배님 사이트의 "3 카테고리 + 카운티 선택 + 슬라이더 + 출처 각주" 골격을 빌리되, **입구를 상황 카드로** 바꾼 것이 차이.

## 4. 화면별 설계 + 빌린 패턴

### 4.0 두 가지 횡단 원칙 (2026-08-21 추가)

**(a) 지역은 행정 위계로 고르고, 분석은 격자로 한다**
- 탐색 단위 = **시·도 › 시·군·구 › 읍·면·동(리)**. 상단 브레드크럼 + 지도 드릴다운(시도 클릭→시군구→동). 선배님의 "주 → 카운티" 드릴다운과 같은 구조.
- 동을 고르면 그 동의 **요약 카드**(인구·고령·반지하·침수이력·대피소 n곳·담당과 전화) + 동 안의 H3 격자가 펼쳐짐. 격자는 "동 안에서 어디가 더 위험한가"를 보여주는 하위 단위.
- 리(里)는 농촌 시군에서만 노출(법정리 경계 사용). 도시는 동까지.
- 데이터: 행안부·통계청 SGIS 읍면동/법정리 경계(전국 공개) → 전국 드릴다운은 **P1부터 전국 지원 가능**.

**(b) 날씨가 필터다** — "무슨 정보가 내게 필요한가"를 시스템이 먼저 고른다
- 기상청 **단기예보(동네예보) API는 읍면동 단위 격자 매핑**을 제공 → 동 선택 즉시 기온·체감온도·강수확률·강수량·풍속.
- **특보 7종**(호우·태풍·강풍·대설·한파·폭염·건조) + 산사태 예·경보 + 하천 수위를 동 단위로 매칭.
- 규칙: 발효 중인 특보가 있으면 → 해당 재난의 상황 카드가 맨 위로, 탭②의 피해 유형 기본값이 그 재난으로, 탭①의 기본 레이어가 그 재난 레이어로 바뀐다. 특보가 없으면 → 계절 기본값(6~9월 호우, 7~8월 폭염, 12~2월 한파·대설).
- 이로써 재난 범위가 침수 단일에서 **폭염·한파**로 자연 확장(둘 다 2018년부터 법정 자연재난; 무더위쉼터·한파쉼터·에너지바우처·냉난방비 지원 규칙 추가).
- 표시 예: "관악구 신림동 · 32.8℃(체감 35℃) · **폭염경보 발효 중** · 가까운 무더위쉼터 3곳 · 오늘 해당되는 지원 2건"

**커버리지 두 층**
| 층 | 범위 | 내용 |
|---|---|---|
| 전국 | 모든 읍면동 | 날씨·특보·재난문자·대피소·쉼터·지원 규칙 매칭(탭②)·특별재난지역 여부 |
| 시범 시군구 | 1곳(→확장) | H3 격자 위험등급·침수이력·취약성·SPA·갭 지도 |
→ 탭②는 **첫 공개부터 전국에서 쓸 수 있고**, 격자 분석만 시범 지역. "not exhaustive"를 지역 커버리지 지도로 정직하게 표시.

### 4.1 입구 (랜딩)
- 상단: 한 문장 + 상황 카드 6장(아이콘+한 줄). 모바일 2열.
- 카드 아래 작은 글씨: "입력 내용은 서버로 전송되지 않습니다(브라우저 안에서만 계산)".
- 빌린 패턴: DisasterAssistance.gov의 **익명 위저드 진입**("질문에 답하면 프로그램을 찾아드립니다") — 로그인 없이 바로.

### 4.2 탭 ① 지도
- 좌: 지도(Leaflet). H3 res 9 격자 choropleth. 기본 레이어 = **종합 위험 등급 1~5**.
- 우(모바일은 하단 시트): 격자 클릭 → **카드 1장**: 등급 숫자 크게 / 근거 3줄(침수이력 n회·최대 침수심·반지하 비율·고령 비율) / 가까운 대피소 2곳(도보 분) / "이 위치로 지원 찾기 →" 버튼.
- 레이어 토글(최대 6): 침수흔적 · 침수예상(100년) · 산사태 · 반지하 · 고령1인 · 대피소.
- 빌린 패턴: First Street **"Flood Factor 7/10" 한 숫자 + 근거 펼침**. NRI의 **격자 choropleth + 사이드 패널 점수 분해**. 선배님의 **반경 슬라이더**("대피소까지 500m 이내?").
- 하지 않는 것: 레이어 30개 나열(생활안전지도 방식).

### 4.3 탭 ② 지원 찾기 ★
**입력(한 화면, 스크롤 없이)**
1. 위치: 지도 클릭 / 주소 검색 / "내 위치" — 격자 자동 확정, 특별재난지역 여부 자동 표시(수동 수정 가능)
2. 나는: 자가 / 전·월세 / 상가·공장 / 농지·축사
3. 피해: 방바닥 위 침수 / 벽·기둥 파손(반파) / 무너짐(전파) / 가재도구만 / 사람이 다침·사망
4. 가구: 기초수급·차상위·한부모 / 65세 이상 / 장애 / 해당 없음 (복수)
5. 재난 종료일: 날짜 1개 (→ D-day 계산)
- "대신 입력 중" 토글(B 페르소나): 결과 화면이 인쇄·공유 중심으로 바뀜.

**결과(한 장, 위→아래 우선순위)**
1. **지금 할 일 3개** — ① 사진 찍기(침수선·가전·서류) ② D-7까지 동 주민센터 피해신고(전화·주소·지도) ③ 피해사실확인서 발급 요청
2. **받을 수 있는 현금 (예상)** — 큰 숫자 합계(예: 550만원 = 재난지원금 350 + 의연금 200) + 항목별 카드(근거 조문·기준일·링크)
3. **한 장으로 자동으로 열리는 것** — 건보료 경감·전기·가스·통신·지방세… (피해사실확인서 기반, §12 17기관)
4. **따로 신청해야 하는 것** — 풍수해보험 청구·소상공인 융자·국세 납기연장·학자금
5. **절차 타임라인** — 신고(D-10) → 현장조사 → 확인서 → 지급 → 이의신청
6. **연락처·서류** — 관할 재난안전과, 필요서류(공동이용으로 생략 가능한 것 표시, 전자정부법 §36)
7. 하단: "이 결과는 2025-11-27 개정 규정·2026-08 고시 단가 기준 예상치입니다" + 규칙 보기 + 정정 제안
- 결과 URL: `#r?h3=8930e1d8a4bffff&own=rent&dmg=flood&hh=senior&end=2026-07-20`
- 빌린 패턴: DisasterAssistance **결과를 기관별이 아닌 '지금 신청 가능' 묶음으로**, 토스 **"숨은 지원금 합계 큰 숫자"**, First Street **"보험료 예상액"** → 여기선 "실부담 보험료".

### 4.4 탭 ③ 어디에 먼저 (SPA)
- 상단 설명 한 줄: "야구의 WPA처럼 — 같은 1억으로 어느 격자의 안전확률이 가장 많이 오르나".
- 좌 지도: 격자별 **SPA/억원** 히트맵. 우 패널: 개입 선택(차수판 보급 / 빗물받이 준설 / 펌프장 증설 / 반지하 이주 지원) + 예산 슬라이더 + "이 격자에 적용" → 전후 안전확률·기대손실·순위 변화.
- 하단: **갭 지도** 토글 — 예상 피해 세대(격자) vs 실제 신고·지급 건수(지자체 복구계획 공개치, 동 단위 → 격자 배분). 빨간 곳 = 사각지대 의심.
- 계수표는 화면에서 바로 열람·수정 가능("당신의 가정으로 다시 계산").
- 빌린 패턴: WRI Aqueduct **Cost-Benefit Analyzer**(시나리오·보호수준 슬라이더), CLIMADA Measure/CostBenefit 개념, 선배님의 **밀도 시각화 토글**.

### 4.5 방법론·규칙·변경 이력
- 방법론: §1의 세 주장 + 데이터 출처 + SPA 수식(단순화본) + 한계.
- 규칙 보기: `rules/*.json`을 표로 렌더. 항목 클릭 → 조문 원문 링크(law.go.kr).
- 변경 이력: 날짜별 "무엇이 바뀌었나"(예: 2025-11-27 소상공인 시설복구 신설 / 2024-08-27 의연금 2배).

## 6. SPA 계산 (공개용 단순화)
- 격자 i의 안전확률 `SE_i = σ(b0 + b1·C_i − b2·H_i − b3·E_i − b4·V_i)`; 지표는 0~1 정규화, **b는 가정값(문헌 범위)**이며 화면에서 수정 가능.
- 기대손실 `EL_i = (1 − SE_i) × 노출자산(건물 수 × 평균 복구단가 + 세대 × 가재도구 단가)`.
- 개입 a: `C_i ← C_i + Δc(a, 예산)`; `SPA_i(a) = SE'_i − SE_i`; `Eff_i(a) = (EL_i − EL'_i) / Cost(a)`.
- 화면은 **순위와 방향**을 강조하고 절대값엔 "가정 기반" 배지.

## 7. 기술 구조
- 정적: `index.html`(입구+탭) + `js/`(map, rules, spa, share) + `css/`. 빌드 도구 없음.
- 지도: Leaflet 1.9(선배님과 동일, 검증됨) + `h3-js`(클릭→격자). 격자 수 천 단위면 충분; 만 단위 넘으면 MapLibre 벡터타일로.
- 실시간: GitHub Actions cron(평시 60분·특보 시 10분) → `data/live/*.json` → Pages. 시크릿: 기상청·safetydata 키.
- 공유: 해시 파라미터 인코딩, 서버 없음. 오프라인: Service Worker로 규칙·격자 캐시.
- 접근성: 글자 18px 기본, 고대비, 키보드, 한국어 우선(영문 방법론 페이지 별도).
- 통계: 기존 site-stats 방식 그대로 연결.
